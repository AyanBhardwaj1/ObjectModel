ObjectModel docs

ObjectModel turns observations of an articulated object (point tracks or video) into a URDF and MJCF model whose joints are measured from motion, then proves the model in MuJoCo before you use it.

Install

pip install "objectmodel[sim,video] @ git+https://github.com/ayanbhardwaj1/objectmodel"
# development
git clone https://github.com/ayanbhardwaj1/objectmodel && cd objectmodel
pip install -e ".[dev]" && python -m pytest -q

Python 3.10+. sim adds MuJoCo (validation), video adds OpenCV (video input). The core needs only NumPy.

Quickstart

objectmodel demo dresser --out out/dresser
open out/dresser/viewer.html

The command prints the verdict and every joint with its confidence and axis uncertainty, then writes five files. Try objectmodel gallery for one page holding every demo object, and objectmodel bench to reproduce the benchmark.

Inputs

Point tracks (any tracker)

A .npz with points of shape (T, N, 3) in metres and visible of shape (T, N). Frame 0 is the rest pose; tracks not visible in frame 0 are dropped with a note. Optional labels (N) with per-track part ids, for example from SAM masks, skip segmentation.

objectmodel fit tracks.npz --hint "kitchen cabinet" --out out/cab
objectmodel fit tracks.npz --labels parts.npy

Video

Built-in Lucas-Kanade tracking with forward-backward checks and automatic background removal. Give a depth stack (T, H, W) in metres for full 3D, or film side-on and set metric scale with a printed ArUco 4×4 marker or one known dimension.

objectmodel video clip.mp4 --depth depth.npy --hint laptop
objectmodel video side.mp4 --marker-mm 50
objectmodel video side.mp4 --scale-mm 304

Hand-held captures work: joints are fitted on motion relative to the parent part and the replay runs in the base's frame.

Outputs

  • <name>.urdf: links with box visual/collision geometry, inertials, joints with limits, effort, velocity and dynamics.
  • <name>.xml: MJCF in radians with nested bodies, hinge/slide joints, ranges and explicit inertials.
  • model.json: the scene for your own tools, including per-frame joint values.
  • report.md: verdict, joint table with uncertainty, masses and every warning.
  • viewer.html: a self-contained 3D viewer with joint sliders and capture replay.

Link frames are axis-aligned at the rest pose; the root's frame is the capture's world origin, so URDF and MJCF place every link identically.

What "validated" means

A model is SIM-VALIDATED only when all of these hold:

  • The MJCF compiles in MuJoCo, and masses, inertias (triangle inequality) and limits are valid.
  • The URDF also compiles, and its link poses match the MJCF within 1 mm at rest, mid-range and both limits.
  • Driving the model with the measured joint values reproduces the tracked points. The error left after removing the expected tracking noise (√6·σ) is under 10 mm.
  • A 2-second passive simulation under gravity stays finite and bounded.

A sweep of each joint through its range also reports parts that would collide, as warnings. Confidence below 0.9 or axis uncertainty above 5° are flagged too.

Python API

from objectmodel.synthetic import TrackSet
from objectmodel.pipeline import run, write_outputs

ts = TrackSet.load("tracks.npz")
result = run(ts, hint="kitchen cabinet")
print(result.validation.passed, result.validation.replay_excess_mm)
for j in result.model.joints:
    print(j.name, j.type, j.axis, j.confidence, j.axis_std_deg)
write_outputs(result, "out/cabinet")

REST API

POST /api/reconstruct on this site runs the same pipeline.

# demo object (JSON body)
curl -X POST {{SITE}}/api/reconstruct -H 'content-type: application/json' \
  -d '{"object":"dresser","noise_mm":2,"camera_motion":0.2,"seed":0}'

# your tracks (raw .npz body, up to 4 MB, 300 frames, 4000 tracks)
curl -X POST '{{SITE}}/api/reconstruct?hint=laptop' --data-binary @tracks.npz

The response holds summary (verdict, joints, warnings), files (URDF, MJCF, JSON, report as text) and viewer_html. Invalid input returns 400 with a message, and a capture with only one rigid part returns 422. GET /api/reconstruct is a health check.

MCP server

{"mcpServers": {"objectmodel": {
  "command": "python", "args": ["-m", "objectmodel.mcp_server"],
  "env": {"OBJECTMODEL_ROOT": "/path/to/workdir"}}}}

Tools: list_demo_objects, reconstruct_demo, reconstruct_tracks, reconstruct_video. Every path is resolved inside OBJECTMODEL_ROOT; anything outside is refused.

LLM naming (optional)

export OBJECTMODEL_LLM_BASE_URL=https://api.llama.com/compat/v1
export OBJECTMODEL_LLM_API_KEY=...
export OBJECTMODEL_LLM_MODEL=...

Any OpenAI-compatible endpoint names parts and joints and picks materials. It never sets geometry. Its reply is validated against the measured structure: unknown ids and materials are dropped, numbers are clamped, and redirects are refused so the key can't leak. Any failure falls back to geometric naming rules and is noted in the report. Use --no-llm to stay offline.

Limitations

  • Collision geometry is one box per part; meshes are on the roadmap.
  • Damping and friction can't be measured from motion alone, so they are defaults.
  • The built-in tracker drifts on large out-of-plane rotations. For those, feed tracks from a long-range tracker such as CoTracker through objectmodel fit.
  • A part whose total motion is close to the tracking noise can't be separated from its parent.
