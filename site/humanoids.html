Plan from the twin. Open the real thing.

A humanoid gets only the measured twin: where the handle is, which way the part moves and how far. It plans its stance and reach from that, then opens the object in a separate MuJoCo world built from the object's ground truth. If the twin were wrong, the arm would be fighting the hinge, and the grasp force would show it.

  • Measured twin: all 10 doors, drawers and lids open, with no more force than a plan using the true joint.
  • Twin with a 2° axis error: 4 of 10 tasks already fail.
  • Runs on the public Apollo model as well as a generic humanoid.

How accurate is accurate enough?

Every first-level door, drawer and lid on five objects, opened by the generic humanoid. Each row plans from ObjectModel's twin, plus a deliberate axis error. Extra force is the grasp force above what the same task needs when planned with the true joint.

ObjectModel's twins land within about 0.2° of the true axis, well below the point where tasks start to fail.

Run it

objectmodel task kitchen_cabinet                 # generic humanoid, door and drawer
objectmodel task kitchen_cabinet --perturb 10    # the same plan from a twin 10° off
objectmodel task-bench                           # the accuracy table above
bash scripts/fetch_menagerie.sh                  # public Apollo model, Apache-2.0
MUJOCO_GL=egl objectmodel task fridge --robot apollo --video fridge.mp4

The Apollo model is Google DeepMind's MuJoCo Menagerie apptronik_apollo, released under Apache-2.0. ObjectModel is an independent project and is not affiliated with or endorsed by Apptronik. Limits: the grasp is a contact constraint rather than finger closure, the pelvis is held at its standing pose, and the robot does not collide with the object during the task.
