Real objects in. Simulation-ready twins out.

How it works

From point tracks to a proven model in five steps

Every number in the output comes from geometry. A language model, if you add one, only names the parts.

  1. Track

    Points are followed through the video (or come from your own tracker) and lifted to metres with depth or an ArUco marker.

  2. Segment

    Sequential RANSAC splits the tracks into rigid parts, with a tolerance that adapts to the measured noise.

  3. Fit joints

    Fixed, sliding and hinged models compete by BIC. The axis comes from the null space of R − I.

  4. Build the tree

    Parts attach where a single joint explains their motion, so lamps chain and cabinets branch. Mass and inertia follow.

  5. Prove it

    MuJoCo compiles the URDF and MJCF, replays your capture, sweeps every joint for collisions and checks stability.

Built for robotics pipelines

Everything you need between a capture and a training run

⟳

Simulator-in-the-loop

Replay error is split into what tracking noise explains and what the model gets wrong, so "passed" means something.

±

Uncertainty per joint

A frame bootstrap tells you when a hinge was barely moved and the axis can't be trusted yet.

▣

Five outputs

URDF, MJCF, a JSON scene, a Markdown report and a self-contained 3D viewer with joint sliders.

◎

Metric scale

Depth maps, a printed ArUco marker, or one known dimension. No guessing how big the cabinet is.

⌘

Agent-ready

An MCP server lets Claude, Llama agents and others create assets as a tool call, confined to a folder you choose.

Aa

Optional LLM naming

Any OpenAI-compatible model names parts and picks materials. Its output is validated; offline rules cover the rest.

Use it your way

CLI, Python, REST or MCP

Terminal
# your own capture (RGB-D)
objectmodel video clip.mp4 --depth depth.npy --hint "kitchen cabinet"

# tracks from any 3D tracker
objectmodel fit tracks.npz --out twins/cabinet

# kitchen_cabinet: SIM-VALIDATED (unexplained 0.0 mm)
#   door_hinge   revolute  body -> door   conf=1.000 ±0.01°
#   drawer_slide prismatic body -> drawer conf=1.000 ±0.07°
REST API
# demo object
curl -X POST /api/reconstruct \
  -H 'content-type: application/json' \
  -d '{"object":"dresser","noise_mm":2}'

# your tracks: points (T,N,3) metres, visible (T,N)
curl -X POST '/api/reconstruct?hint=laptop' \
  --data-binary @tracks.npz
